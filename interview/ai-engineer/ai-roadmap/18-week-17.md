A model on your laptop helps nobody. This week you learn the standard way AI apps reach users: a FastAPI service, packed in a Docker container, running on a cloud platform. By Day 119 your RAG chatbot from Project 1 should have a public URL.

> **In simple words:** FastAPI turns your Python functions into a web service. Docker packs the service and everything it needs into one box that runs the same everywhere. The cloud rents you computers to run that box for real users.

## What each topic means

**Serving an LLM endpoint.** An API route that receives a question, calls an LLM (through an SDK or a local model), and returns the answer. Your service sits between users and the model, adding RAG, rules, logging and limits.

**SSE (Server-Sent Events).** A simple web standard for the server to push a stream of messages over one HTTP response. Chat apps use it to show LLM tokens as they arrive. In FastAPI you return a `StreamingResponse`.

**Background task.** Work that runs after the response is sent, like indexing an uploaded PDF or writing logs, so the user does not wait. For heavy jobs use a proper queue (Celery, RQ, or a cloud queue).

**Authentication vs authorization.** **Authentication** checks who you are (API key, login token). **Authorization** checks what you may do (only admins can delete documents).

**API key header.** A simple auth method: the client sends a secret in a header like `X-API-Key`, and the server checks it. Fine for demos; real user apps use login tokens.

**JWT (JSON Web Token).** A signed token the server gives after login. The client sends it with each request, and the server can verify it without a database lookup.

**HTTP status codes.** Numbers that describe the result: 200 OK, 201 created, 400 bad request, 401 not authenticated, 403 forbidden, 404 not found, 422 validation error (FastAPI's default for bad input), 429 too many requests, 500 server error, 503 service unavailable.

**TestClient.** FastAPI's tool to call your routes in tests without starting a server.

**Mocking.** Replacing a real dependency (like the LLM API) with a fake in tests, so tests are fast, free and repeatable, and you can simulate failures.

**Timeout.** A maximum wait time for an external call. Always set one for LLM API calls, and decide what to return when it fires.

**Docker.** A tool that packages an app with its exact Python version, libraries and settings into an image, so it runs the same on your laptop, a teammate's laptop and the cloud. "It works on my machine" stops being a problem.

**Image vs container.** An **image** is the packed, read-only template. A **container** is a running instance of an image. One image can run as many containers.

**Dockerfile.** The recipe for an image: start from a base image (`FROM python:3.12-slim`), copy files, install requirements, and set the start command.

**Layer and build cache.** Each Dockerfile instruction creates a layer. Docker reuses unchanged layers, so copy `requirements.txt` and install packages before copying your code; then code changes rebuild in seconds.

**Port mapping.** `-p 8000:8000` connects port 8000 on your machine to port 8000 inside the container.

**Volume.** Storage outside the container's own filesystem, so data (like the vector DB) survives when the container is removed.

**Container registry.** A store for images, like Docker Hub, AWS ECR, Google Artifact Registry or Azure Container Registry. The cloud pulls your image from there.

**docker compose.** A tool to define and run several containers together from one YAML file: your API, the vector DB and Redis, with their networks and volumes.

**Redis.** A very fast in-memory key–value store, often used as a cache, a rate-limit counter or a simple queue.

**Slim image.** A small base image (like `python:3.12-slim`) without extra tools. Smaller images download and start faster and have fewer security holes.

**GPU image.** A base image with NVIDIA CUDA libraries, needed to run models on a GPU inside a container.

**Secrets.** Passwords and API keys. Pass them as environment variables or through the platform's secret manager; never bake them into the image or commit them to Git.

**Cloud.** Renting computing resources (servers, storage, GPUs, managed services) over the internet and paying for what you use. The big three are AWS, Microsoft Azure and Google Cloud (GCP).

**EC2 and S3 (AWS).** **EC2** is a rented virtual machine. **S3** is object storage for files like PDFs, datasets and model weights.

**SageMaker (AWS).** A managed service to train, tune and deploy ML models.

**Bedrock (AWS).** A managed service to call foundation models from several providers (including Claude) through AWS, with AWS security and billing.

**Lambda (AWS).** Serverless functions: upload code and AWS runs it on each request. Cheap for small, short tasks; limited for heavy ML workloads.

**Azure OpenAI.** Microsoft's service for using OpenAI models inside Azure, popular with large enterprises.

**Vertex AI (GCP).** Google Cloud's ML platform for training, deploying and calling models, including Google's Gemini models.

**Cloud Run, ECS, App Runner.** Services that run your container for you. **Cloud Run** (GCP) and **App Runner** (AWS) are the simplest: give an image, get a URL. **ECS** (AWS) gives more control for larger systems.

**Which cloud to learn first.** Check job posts in your target city and companies. AWS has the largest share overall; Azure is common in enterprises and service companies; GCP is popular with start-ups. The concepts transfer, so pick one and learn it well.

**Budget alert.** A setting that emails you when spending passes a limit. Set one before deploying anything.

**Second pass (DSA).** Going through the patterns again with harder problems and without the book open, to turn recognition into recall.

**Mock interview.** A timed practice interview: unseen problems, talking aloud, no running code until you have traced it by hand. Recording yourself shows silences and unclear explanations.

## End-of-week self-check

1. Why do chat apps stream responses? How does FastAPI do it?
2. What is the difference between authentication and authorization?
3. Why should you copy `requirements.txt` and run `pip install` before copying your code in a Dockerfile?
4. What is the difference between an image and a container?
5. Your vector DB data disappears every time you restart the container. Why, and what is the fix?
6. Where should your Anthropic API key live in production?
7. You need to deploy a small FastAPI RAG demo cheaply. Which kind of cloud service would you choose, and why?
8. What should you do in a mock interview when you get stuck for 5 minutes?

**Answers**

1. LLM answers can take many seconds; streaming shows the first words in under a second, so the app feels fast. FastAPI returns a `StreamingResponse` that yields chunks (for example as Server-Sent Events) while the LLM generates them.
2. Authentication checks who the caller is (key, token, login). Authorization checks whether that caller is allowed to perform this specific action.
3. Docker caches layers. Requirements change rarely, so the slow install layer is reused; only the fast "copy code" layer rebuilds when you change code.
4. An image is a read-only package (the template). A container is a running instance of that image, with its own writable layer and process.
5. Data written inside the container's filesystem is lost when the container is removed or recreated. Mount a volume for the database's data folder.
6. In the platform's secret manager or as an environment variable set on the service, read by the code at start-up. Never in code, the image, or Git.
7. A serverless container platform such as Cloud Run or App Runner: you give it the image, it gives you an HTTPS URL, it scales automatically, and Cloud Run can scale to zero so an idle demo costs very little. Keep the vector DB small and inside the container or on a free managed tier.
8. Say what you are thinking, return to a brute-force solution and state its complexity, look at a small example by hand to spot a pattern, and name candidate patterns aloud ("sorted input, so two pointers or binary search?"). Interviewers often give a hint when they hear your reasoning.
