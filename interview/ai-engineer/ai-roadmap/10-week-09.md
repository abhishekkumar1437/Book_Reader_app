This week you move from math on paper to real deep learning code. PyTorch is the most used deep learning library in research and industry, and its training loop is something you should be able to write from memory. Then you learn the two classic architectures: CNNs for images and RNNs/LSTMs for sequences. Day 63 prepares you for next week's image classifier project.

> **In simple words:** PyTorch does the gradient math for you. You define the model, pick a loss and an optimizer, and repeat four lines: predict, compute loss, backpropagate, update. CNNs slide small filters over images to find patterns; RNNs read sequences one step at a time while remembering what came before.

The training loop to know by heart (Day 59):

```python
for epoch in range(num_epochs):
    model.train()                          # turn on dropout / batch-norm training mode
    for xb, yb in train_loader:
        xb, yb = xb.to(device), yb.to(device)
        optimizer.zero_grad()              # 1. clear old gradients
        logits = model(xb)                 # 2. forward pass
        loss = loss_fn(logits, yb)         # 3. compute loss
        loss.backward()                    # 4. backpropagate
        optimizer.step()                   # 5. update weights

    model.eval()                           # turn off dropout, use running batch-norm stats
    with torch.no_grad():                  # no gradients needed for validation
        ...                                # compute validation loss and accuracy
```

## What each topic means

**Dropout.** During training, randomly switch off a fraction of neurons (for example 20%) at each step. The network cannot depend on any single neuron, so it generalises better. At test time dropout is off and all neurons are used.

**Weight decay.** A penalty that pulls weights towards zero at every step (L2 regularization). In AdamW it is applied directly to the weights.

**Batch normalization.** Normalises each feature across the examples in a mini-batch (mean 0, std 1), then rescales with learned values. It speeds up and stabilises training in CNNs. Behaves differently in train and eval mode.

**Layer normalization.** Normalises across the features of each single example instead of across the batch. Works the same for any batch size, so Transformers use it.

**Early stopping.** Stop training when the validation loss has not improved for a few epochs, and keep the best checkpoint.

**Data augmentation.** Creating new training examples by changing existing ones slightly: flipping, cropping or rotating images. The model sees more variety and overfits less.

**Tensor.** PyTorch's array, like a NumPy array but able to run on a GPU and track gradients. A batch of 32 colour images of 224×224 pixels is a tensor of shape (32, 3, 224, 224).

**Device.** Where a tensor lives: `"cpu"` or `"cuda"` (an NVIDIA GPU), or `"mps"` on Apple chips. The model and the data must be on the same device.

**Autograd.** PyTorch's automatic differentiation. It records operations on tensors with `requires_grad=True` and computes all gradients when you call `.backward()`.

**`requires_grad` and `.grad`.** `requires_grad=True` tells PyTorch to track a tensor for gradients. After `loss.backward()`, the gradient is stored in `tensor.grad`.

**`nn.Module`.** The base class for every PyTorch model. You create layers in `__init__` and describe the forward pass in `forward`.

**Dataset and DataLoader.** A **Dataset** says how to get one example (`__len__` and `__getitem__`). A **DataLoader** groups examples into shuffled mini-batches and can load them in parallel.

**`zero_grad`, `backward`, `step`.** PyTorch adds new gradients to old ones, so you clear them with `optimizer.zero_grad()`, compute new ones with `loss.backward()`, and update weights with `optimizer.step()`.

**Train vs eval mode.** `model.train()` turns on dropout and batch-norm training behaviour; `model.eval()` turns them off for validation and inference. Forgetting `eval()` is a classic bug.

**`torch.no_grad()`.** A block where PyTorch does not track gradients. Use it for validation and inference to save memory and time.

**`state_dict`.** A dictionary of all the model's learned weights. Save with `torch.save(model.state_dict(), "model.pt")` and load with `model.load_state_dict(...)`.

**GPU and CUDA.** A **GPU** does thousands of simple math operations in parallel, which is perfect for matrix multiplies. **CUDA** is NVIDIA's platform that PyTorch uses to run on GPUs.

**Mixed precision.** Doing most math in 16-bit numbers (float16 or bfloat16) instead of 32-bit to train faster with less memory, while keeping sensitive parts in 32-bit.

**Gradient clipping.** Capping the size of gradients before the update so one bad batch cannot blow up training.

**Overfit one batch.** A debugging trick: train on a single small batch. A correct model and loop should drive the loss close to zero. If it cannot, there is a bug.

**Seed (reproducibility).** Fixing random seeds (`torch.manual_seed(42)`) so runs can be repeated with the same results.

**Convolution.** Sliding a small grid of weights (a **filter** or **kernel**, for example 3×3) over an image and computing a dot product at each position. Each filter learns to detect one pattern, such as an edge.

**Feature map.** The output grid of one filter: where in the image the pattern appears.

**Stride and padding.** **Stride** is how many pixels the filter moves each step. **Padding** adds a border of zeros so the output does not shrink. Output size = (n + 2p − k) / s + 1. For a 5×5 input, 3×3 filter, stride 1, no padding: (5 − 3)/1 + 1 = 3, so 3×3. For a 28×28 input with padding 1: (28 + 2 − 3)/1 + 1 = 28.

**Pooling.** Shrinking a feature map by taking the maximum (max pooling) or average of small regions, for example 2×2. It reduces size and makes the network less sensitive to small shifts.

**CNN (Convolutional Neural Network).** A network built from convolution and pooling layers, usually followed by a few fully connected layers. Early layers find edges, deeper layers find shapes and objects.

**ResNet and skip connections.** A **skip (residual) connection** adds a layer's input to its output: output = F(x) + x. Gradients can flow straight through, so very deep networks (50, 100+ layers) can train. Transformers use the same idea.

**Sequence data.** Data where order matters: text, speech, stock prices, sensor readings.

**RNN (Recurrent Neural Network).** A network that reads a sequence one step at a time, keeping a **hidden state**, a vector that summarises what it has seen so far.

**LSTM (Long Short-Term Memory).** An RNN with a separate memory (the cell state) and three **gates**: the **forget gate** decides what to erase, the **input gate** what to write, and the **output gate** what to show. It remembers over longer sequences than a plain RNN.

**GRU.** A simpler version of the LSTM with two gates. Often similar accuracy, fewer parameters.

**Why Transformers replaced RNNs.** RNNs must process tokens one after another, so they are slow to train on GPUs, and they still forget information from far back. Transformers look at all tokens at once with attention (Week 11).

**Transfer learning.** Reusing a model trained on a big dataset (like ImageNet) for your smaller task. You start from good features instead of from random weights.

**Feature extraction vs fine-tuning.** **Feature extraction**: freeze the pretrained layers and train only a new final layer. **Fine-tuning**: also update some or all pretrained layers, usually with a small learning rate.

**Freezing layers.** Setting `requires_grad = False` on parameters so they do not change during training.

**Heap (DSA).** A tree-shaped structure that always gives the smallest (min-heap) item in O(1) and adds or removes items in O(log n). Python's `heapq` is a min-heap.

**Top-k pattern (DSA).** To find the k largest items, keep a min-heap of size k; if a new item is bigger than the heap's smallest, replace it. Time O(n log k).

## End-of-week self-check

1. What are the five steps inside the PyTorch training loop, in order?
2. Why must you call `optimizer.zero_grad()`?
3. What do `model.eval()` and `torch.no_grad()` each do? Do you need both?
4. A 32×32 image goes through a 5×5 filter with stride 1 and no padding. What is the output size?
5. Why do CNNs work better than plain fully connected networks on images?
6. What problem do skip connections solve?
7. What does the forget gate in an LSTM do?
8. You have only 2,000 labelled images of 5 types of crops. How would you build a classifier?

**Answers**

1. Zero the gradients, forward pass, compute the loss, `loss.backward()`, `optimizer.step()`.
2. PyTorch adds new gradients to the ones already stored. Without clearing, gradients from earlier batches add up and the updates are wrong.
3. `model.eval()` switches layers like dropout and batch norm to inference behaviour. `torch.no_grad()` stops gradient tracking to save memory and time. They do different things, so for validation you normally use both.
4. (32 − 5)/1 + 1 = 28, so 28×28.
5. Filters share weights across the whole image, so there are far fewer parameters, and they find local patterns (edges, textures) wherever they appear. A fully connected layer treats every pixel separately and ignores that nearby pixels are related.
6. Vanishing gradients and the difficulty of training very deep networks. Adding the input to the output lets gradients flow directly backwards, so even 100+ layer networks train well.
7. It decides, for each part of the cell state, how much of the old memory to keep and how much to erase, based on the current input and the previous hidden state.
8. Transfer learning: take a pretrained CNN like ResNet, replace the last layer with a 5-class layer, train only that layer first (feature extraction), then optionally fine-tune the last few blocks with a small learning rate, using data augmentation.
