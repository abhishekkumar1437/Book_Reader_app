## What each topic means

**KNN (K-Nearest Neighbours).** To classify a new point, find the k closest training points and take a majority vote. No real "training"; all the work happens at prediction time.

**Distance metrics.** Ways to measure "closeness". **Euclidean** is the straight-line distance: from (1, 2) to (4, 6) it is √(3² + 4²) = 5. **Manhattan** adds the absolute differences: 3 + 4 = 7. **Cosine distance** compares directions and is used for text embeddings.

**Curse of dimensionality.** With very many features, all points become far from each other and distances stop being meaningful. KNN and clustering get worse; reducing dimensions helps.

**SVM (Support Vector Machine).** A classifier that finds the boundary with the widest gap (the **margin**) between classes. The closest points that define the margin are the **support vectors**.

**Kernel.** A trick that lets an SVM draw curved boundaries by implicitly mapping data into a higher-dimensional space. Common kernels: linear, polynomial, RBF.

**Naive Bayes.** A fast classifier based on Bayes' theorem that "naively" assumes features are independent given the class. Works surprisingly well for spam filtering using word counts.

**Clustering.** Grouping similar items without labels, like segmenting Flipkart customers into "bargain hunters", "frequent buyers" and "festive-season buyers".

**K-Means.** Pick k centres, assign each point to its nearest centre, move each centre to the mean of its points, and repeat until nothing changes. You must choose k.

**Centroid.** The centre (mean point) of a cluster.

**Elbow method.** Plot the total within-cluster distance for k = 1, 2, 3, …; the "elbow" where the curve stops falling quickly suggests a good k.

**Silhouette score.** From −1 to 1, how well each point fits its own cluster compared to the next closest cluster. Higher is better.

**DBSCAN.** A clustering method that groups dense regions and marks isolated points as noise. It finds clusters of any shape and does not need k, but needs a distance radius (`eps`) and a minimum number of points.

**Hierarchical clustering.** Builds a tree of clusters by repeatedly merging the closest groups. The tree (**dendrogram**) lets you cut at any number of clusters.

**Dimensionality reduction.** Reducing the number of features while keeping most of the information. Helps speed, visualisation and the curse of dimensionality.

**Explained variance.** For PCA, the share of the data's total variance each component keeps. "The first 10 components explain 95% of the variance" means 10 features keep 95% of the spread.

**t-SNE and UMAP.** Methods to squash high-dimensional data into 2-D or 3-D for plotting, keeping similar points close. Use them for visualisation only, not as model features; distances between far-apart clusters in the plot do not mean much.

**Confusion matrix.** A table of correct and wrong predictions: **TP** (true positive: predicted yes, really yes), **FP** (false positive: predicted yes, really no), **FN** (false negative: predicted no, really yes), **TN** (true negative).

**Accuracy.** (TP + TN) / total. Misleading when classes are imbalanced.

**Precision.** TP / (TP + FP). "Of everything I flagged, how much was right?" Important when false alarms are costly, like marking a real email as spam.

**Recall (sensitivity).** TP / (TP + FN). "Of all real positives, how many did I catch?" Important when misses are costly, like missing cancer or fraud.

**F1 score.** The harmonic mean of precision and recall: 2 · P · R / (P + R). One number that is high only when both are high.

Worked example: 100 emails. TP = 30, FP = 10, FN = 20, TN = 40. Accuracy = 70/100 = 0.70. Precision = 30/40 = 0.75. Recall = 30/50 = 0.60. F1 = 2 × 0.75 × 0.60 / 1.35 = 0.90 / 1.35 ≈ 0.667.

**ROC curve and ROC-AUC.** The ROC curve plots recall (true positive rate) against the false positive rate for every threshold. **AUC** (area under the curve) is 1.0 for a perfect ranker and 0.5 for random guessing.

**PR-AUC.** The area under the precision–recall curve. Better than ROC-AUC when positives are rare, like fraud.

**Regression metrics.** **MAE** is the average absolute error (in ₹, easy to explain). **RMSE** is the square root of MSE (in the same units, punishes big errors). **R²** is the share of variance explained. **MAPE** is the average percentage error (breaks when actual values are near zero).

**Overfitting and underfitting.** **Overfitting**: the model memorises training data, so train score is high but validation score is much lower. **Underfitting**: the model is too simple, so both scores are low.

**Bias–variance trade-off.** **Bias** is error from wrong, too-simple assumptions (underfitting). **Variance** is error from being too sensitive to the particular training data (overfitting). Making a model more complex lowers bias but raises variance; you look for the balance.

**Learning curve.** A plot of train and validation scores as the training set grows. It shows whether more data would help.

**Regularization.** Adding a penalty for large weights to keep the model simpler. **L2 (Ridge)** shrinks all weights smoothly. **L1 (Lasso)** can push some weights exactly to zero, which selects features. **ElasticNet** mixes both.

**k-fold cross-validation.** Split the training data into k parts; train on k − 1 and validate on the remaining one, k times, and average the scores. More reliable than a single split.

**Stratified split.** A split that keeps the same class proportions in every part. Essential for imbalanced data.

**Time-series split.** For data over time, always train on the past and validate on the future. Random splits would let the model "see the future".

**Pipeline.** A scikit-learn object that chains steps (impute → encode → scale → model) so they are fitted only on training data in each fold. It prevents leakage and makes deployment simple.

**ColumnTransformer.** Applies different preprocessing to different columns, for example one-hot for `city` and scaling for `income`.

**Hyperparameter.** A setting you choose before training (tree depth, number of trees, learning rate), as opposed to **parameters** the model learns (weights).

**Grid search, random search, Optuna.** **Grid search** tries every combination from a list. **Random search** tries random combinations and is often as good with less time. **Optuna** searches smartly, using earlier results to pick the next try.

**joblib.** A library to save a trained model or pipeline to a file and load it later: `joblib.dump(pipe, "model.joblib")`.

**Churn.** When a customer stops using a service (cancels a subscription, leaves a telecom operator). Predicting churn lets a company offer discounts before the customer leaves.

**Intervals (DSA).** Problems about ranges like meeting times. The usual trick: sort by start time, then sweep left to right, merging or counting overlaps.

**Quickselect (DSA).** Finds the k-th largest item in average O(n) time by partitioning like quicksort but only recursing into one side.

## End-of-week self-check

1. Point A is (0, 0) and B is (3, 4). What are the Euclidean and Manhattan distances?
2. When would you choose DBSCAN over K-Means?
3. A cancer test has TP = 45, FN = 5, FP = 20, TN = 930. Compute precision and recall. Which matters more here?
4. Why is accuracy a poor metric for fraud detection? What would you use?
5. Train accuracy is 99%, validation accuracy is 75%. What is happening and name three fixes.
6. What is the difference between L1 and L2 regularization?
7. Why should scaling be inside the pipeline instead of done before cross-validation?
8. How do you merge overlapping intervals?

**Answers**

1. Euclidean = √(9 + 16) = 5. Manhattan = 3 + 4 = 7.
2. When clusters have odd shapes, when you do not know how many clusters there are, or when you want to find outliers (DBSCAN marks them as noise).
3. Precision = 45 / (45 + 20) = 45/65 ≈ 0.69. Recall = 45 / (45 + 5) = 45/50 = 0.90. Recall matters more: missing a cancer (false negative) is far worse than a false alarm, which a second test can clear.
4. Fraud is rare, so predicting "not fraud" every time gives very high accuracy while catching nothing. Use recall, precision, F1 or PR-AUC, and choose the threshold based on the cost of misses vs false alarms.
5. Overfitting. Fixes: a simpler model (lower depth, fewer features), regularization, more training data, or early stopping; also check for leakage.
6. L1 adds the sum of absolute weights to the loss and can push some weights to exactly zero, so it selects features. L2 adds the sum of squared weights and shrinks all weights smoothly but rarely to zero.
7. If you scale before cross-validation, each validation fold has already influenced the mean and standard deviation, which leaks information. Inside a pipeline, the scaler is refitted on only the training part of each fold.
8. Sort intervals by start. Walk through them; if the current interval starts before or at the end of the last merged one, extend the end to the larger end; otherwise start a new merged interval. O(n log n) for the sort.
