Pandas warm-up for Day 16 (a tiny table you can type in):

```python
import pandas as pd

orders = pd.DataFrame({
    "customer": ["Asha", "Ravi", "Asha", "Meena", "Ravi"],
    "city":     ["Pune", "Delhi", "Pune", "Chennai", "Delhi"],
    "amount":   [1200, 450, 3000, None, 800],
})
print(orders["amount"].mean())                         # 1362.5 (NaN is skipped)
print(orders.groupby("customer")["amount"].sum())      # Asha 4200, Meena 0, Ravi 1250
print(orders[orders["amount"] > 1000])                 # rows 0 and 2
print(orders["amount"].fillna(0).sum())                # 5450.0
```

## What each topic means

**Broadcasting.** NumPy's rule for doing math between arrays of different shapes. It stretches the smaller one (without copying) when shapes are compatible. A `(3, 4)` array plus a `(4,)` array adds the same 4 numbers to each of the 3 rows. Shapes are compared from the right; each pair must be equal or one of them must be 1.

**axis.** Which direction an operation runs along. For a 2-D array, `axis=0` goes down the rows (one result per column) and `axis=1` goes across the columns (one result per row). For a students × subjects array, `mean(axis=1)` gives each student's average.

**Aggregation.** Turning many values into one: sum, mean, max, min, count.

**Random seed.** A starting number for the random generator. The same seed gives the same "random" numbers every time, so experiments can be repeated. `rng = np.random.default_rng(42)`.

**Matrix multiplication (`@`).** Rows of the first array times columns of the second. Shapes `(2, 3) @ (3, 4)` give `(2, 4)`. You will learn it properly on Day 23.

**Series.** One column of data with labels (an index). Like one column of an Excel sheet.

**DataFrame.** A table of rows and columns in Pandas. Each column is a Series.

**Index.** The row labels of a DataFrame. By default 0, 1, 2, … but can be dates or IDs.

**`loc` vs `iloc`.** `loc` selects by label (`df.loc[5, "amount"]`); `iloc` selects by position (`df.iloc[0, 2]` is the first row, third column).

**groupby.** Split rows into groups, apply a calculation to each group, and combine the results. "Average marks per class" is `df.groupby("class")["marks"].mean()`.

**merge.** Joining two DataFrames on a common column, like a SQL join. `orders.merge(customers, on="customer_id")`.

**NaN (missing value).** "Not a Number", Pandas' marker for a missing value. Most calculations skip it. `isna()` finds them, `fillna()` fills them, `dropna()` removes rows that have them.

**EDA (Exploratory Data Analysis).** Looking at data before modelling: size, column types, missing values, distributions, outliers, and relationships between columns. It prevents many modelling mistakes.

**Histogram.** A bar chart of how many values fall in each range. It shows the shape of one column, for example how exam marks are spread.

**Scatter plot.** Dots for pairs of values, one dot per row. It shows if two columns move together, for example study hours vs marks.

**Box plot.** A chart showing the median, the middle 50% of values, and outliers.

**Git.** A tool that records the history of your files. You can go back to any saved version and work on new features safely.

**Repository (repo).** A project folder tracked by Git, including its full history.

**Commit.** A saved snapshot of your changes, with a message. `git commit -m "Add EDA notebook"`.

**Staging area.** Where you put changes before committing. `git add file.py` stages a file.

**Branch.** A separate line of work. You build a feature on a branch without touching `main`, then **merge** it back.

**Remote, push, pull.** A **remote** is a copy of the repo on a server like GitHub. **push** sends your commits up; **pull** brings others' commits down.

**Pull request (PR).** A request on GitHub to merge a branch, where others review the changes first.

**`.gitignore`.** A file listing what Git should never track, such as `.venv/`, `__pycache__/`, `.env` (secrets!) and large data files.

**Terminal / shell.** A text window where you type commands. On Linux and Mac the usual shell is bash or zsh; servers and Docker containers are almost always Linux, so you need these commands.

**Path.** The address of a file, like `/home/asha/projects/app.py`. `.` means the current folder and `..` means the folder above.

**Pipe (`|`).** Sends the output of one command into another. `cat log.txt | grep ERROR | wc -l` counts error lines.

**grep.** Searches for text in files. `grep -r "api_key" .` finds every file that mentions `api_key`.

**Environment variable.** A named value set outside your code, read with `os.environ["NAME"]`. API keys go here, never in code. `export ANTHROPIC_API_KEY=...` on Linux.

**Permissions (`chmod`).** Who can read, write or run a file. `chmod +x run.sh` makes a script runnable.

**SQL.** The language for asking questions of a relational database. `SELECT name FROM students WHERE marks > 90;`.

**Table, row, column.** A table stores one kind of thing (customers); each row is one item (one customer); each column is one property (name, city).

**Primary key and foreign key.** A **primary key** uniquely identifies each row (customer_id). A **foreign key** in another table points to it (orders.customer_id), which is how tables are linked.

**JOIN.** Combines rows from two tables. **INNER JOIN** keeps only matches; **LEFT JOIN** keeps all rows from the left table, with NULLs where there is no match.

**GROUP BY and HAVING.** `GROUP BY` makes groups for aggregates; `WHERE` filters rows before grouping; `HAVING` filters groups after grouping.

**Subquery and CTE.** A **subquery** is a query inside another query. A **CTE** (`WITH name AS (...)`) is a named subquery written first, which makes long queries readable.

**Window function.** Computes a value across related rows without collapsing them, for example a rank within each department: `RANK() OVER (PARTITION BY dept ORDER BY salary DESC)`.

**Σ (sigma) notation.** Means "add up". Σ xᵢ for i = 1 to 3 means x₁ + x₂ + x₃. You start reading math like this on Day 21.

**Prefix sum (DSA).** An array where position i stores the sum of all items before it. The sum of any range is then one subtraction. Combined with a hash map it counts subarrays with a given sum in O(n).

**Hash map (DSA).** Python's dict used as a fast lookup table: "have I seen this value, and where?".

## End-of-week self-check

1. A has shape `(5, 3)` and B has shape `(3,)`. What is the shape of `A + B`? What about `A + C` where C has shape `(5,)`?
2. What is the difference between `df.loc[2]` and `df.iloc[2]`?
3. How do you get the average `amount` per `city` in Pandas?
4. What is the difference between `git commit` and `git push`?
5. Why should `.env` be in `.gitignore`?
6. What is the difference between WHERE and HAVING?
7. Write (aloud) a query to find the second highest salary in an `employees` table.
8. Why does sliding window not work for "count subarrays with sum k" when numbers can be negative?

**Answers**

1. `A + B` is `(5, 3)`: B's 3 values are added to every row. `A + C` fails: comparing from the right, 3 vs 5 are not equal and neither is 1. You would need `C.reshape(5, 1)`.
2. `loc[2]` gets the row whose index label is 2. `iloc[2]` gets the third row by position. They differ after sorting or filtering, when labels no longer match positions.
3. `df.groupby("city")["amount"].mean()`.
4. `commit` saves a snapshot in your local repository. `push` sends your commits to the remote (GitHub) so others, and your other machines, can see them.
5. It holds secrets like API keys. If it is pushed, anyone who can see the repo can use your keys and spend your money. Bots scan GitHub for leaked keys within minutes.
6. WHERE filters individual rows before grouping. HAVING filters whole groups after GROUP BY, so it can use aggregates like `SUM(amount) > 5000`.
7. One way: `SELECT MAX(salary) FROM employees WHERE salary < (SELECT MAX(salary) FROM employees);`. Another: `DENSE_RANK() OVER (ORDER BY salary DESC)` in a CTE, then pick rank 2.
8. Sliding window needs the sum to grow when the window grows and shrink when it shrinks. With negative numbers, adding an item can make the sum smaller, so you cannot know which way to move. Prefix sums with a hash map work for any numbers.
