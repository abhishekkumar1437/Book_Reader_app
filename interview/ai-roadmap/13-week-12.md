The first three days finish Phase 5 with practical tools: the Hugging Face library and fine-tuning a real Transformer. From Day 81 you start Phase 6, the core of the AI Engineer job. You learn what an LLM really is, how it is trained into a helpful assistant, what temperature and the context window do, and how to call LLMs from Python.

> **In simple words:** Hugging Face is the app store and toolbox for open AI models. An LLM is a huge Transformer trained to predict the next token; extra training makes it follow instructions. When you call it, settings like temperature control how creative the answer is, and the context window limits how much text it can see at once.

Temperature by hand (Day 83). Logits [2, 1, 0]:

```text
T = 1.0:   e^2 = 7.389, e^1 = 2.718, e^0 = 1.000, sum = 11.107
           probabilities = 0.665, 0.245, 0.090
T = 0.5:   divide logits by 0.5 -> [4, 2, 0]
           e^4 = 54.598, e^2 = 7.389, e^0 = 1.000, sum = 62.987
           probabilities = 0.867, 0.117, 0.016
```

Lower temperature makes the top token even more likely, so answers become more focused and repeatable.

A first API call for Day 84 (set `ANTHROPIC_API_KEY` in your environment first, and check the current model names in the provider's docs):

```python
import anthropic

client = anthropic.Anthropic()                       # reads ANTHROPIC_API_KEY from the environment
msg = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=300,
    system="You are a patient tutor. Answer in simple English.",
    messages=[{"role": "user", "content": "Explain the KV cache in 3 sentences."}],
)
print(msg.content[0].text)
print(msg.usage.input_tokens, msg.usage.output_tokens)  # use these to estimate cost
```

## What each topic means

**Open-weight model.** A model whose trained weights you can download and run yourself (Llama, Mistral, Qwen, Gemma). Check the **licence**: some allow any commercial use, some have limits.

**Closed (API) model.** A model you can only use through the company's API, like Claude or GPT. You do not get the weights.

**Hugging Face Hub.** A website hosting hundreds of thousands of models and datasets that you can load by name.

**`pipeline`.** The simplest Hugging Face API: `pipeline("sentiment-analysis")("I loved the movie")` handles tokenising, running the model and decoding in one call.

**`AutoTokenizer` and `AutoModel`.** Classes that load the right tokenizer and model for any model name on the Hub, for example `AutoModelForSequenceClassification.from_pretrained("distilbert-base-uncased", num_labels=2)`.

**`datasets` library.** Loads and processes datasets efficiently, with `map` to tokenise every example.

**`Trainer`.** A Hugging Face class that runs the training loop (batches, optimizer, evaluation, saving) for you.

**LLM (Large Language Model).** A very large decoder-only Transformer trained on huge amounts of text to predict the next token. "Large" means billions of parameters.

**Parameters.** The learned numbers (weights) inside the model. A "7B" model has about 7 billion.

**Scaling laws.** The observation that loss falls in a smooth, predictable way as you increase model size, data and compute together.

**Emergent abilities.** Skills that seem to appear only at larger scales, like multi-step reasoning. Researchers still debate how sudden these really are.

**Hallucination.** When an LLM states something false with confidence. It happens because the model is trained to produce likely text, not to check facts; it may have never seen the fact, or the prompt may push it to guess.

**Pretraining.** The first, most expensive stage: next-token prediction on trillions of tokens of web text, books and code. The result is a **base model** that continues text but does not follow instructions well.

**SFT (Supervised Fine-Tuning) / instruction tuning.** Training the base model on examples of instructions and good answers, so it learns to act as a helpful assistant.

**RLHF (Reinforcement Learning from Human Feedback).** Humans compare pairs of answers; a **reward model** learns to predict which answer people prefer; then the LLM is trained to produce answers the reward model scores highly.

**DPO (Direct Preference Optimization).** A simpler alternative to RLHF that trains directly on preferred vs rejected answer pairs, without a separate reward model or RL loop.

**Reasoning (thinking) models.** Models trained, often with reinforcement learning on problems with checkable answers, to write out intermediate reasoning before the final answer. They do better on math, code and planning, but use more tokens and time.

**Safety training / Constitutional AI.** Training that teaches the model to refuse harmful requests and follow rules. Constitutional AI (from Anthropic) uses a written list of principles and AI feedback to guide this.

**Logits.** The raw scores the model outputs for every token in the vocabulary before softmax.

**Greedy decoding.** Always pick the most likely next token. Repeatable, but can be dull or repetitive.

**Sampling.** Pick the next token randomly according to the probabilities, so answers vary.

**Temperature.** Divides the logits before softmax. Below 1 makes the distribution sharper (more focused), above 1 makes it flatter (more random). Use low temperature for extraction and code, higher for brainstorming.

**Top-k.** Sample only from the k most likely tokens.

**Top-p (nucleus sampling).** Sample from the smallest set of tokens whose probabilities add up to p (for example 0.9). Adapts to how confident the model is.

**Max tokens.** The maximum number of tokens the model may generate in the answer. It is a limit, not a target.

**Stop sequence.** A string that makes generation stop when it appears, like `"\n\nUser:"`.

**Context window.** The maximum number of tokens (prompt + answer) the model can handle at once. Modern models range from tens of thousands to around a million tokens.

**KV cache.** During generation, the keys and values of earlier tokens are stored so they are not recomputed for every new token. It makes generation much faster but uses a lot of GPU memory for long contexts.

**Long-context trade-offs.** Putting more text in the prompt costs more, is slower, and models may pay less attention to information in the middle of very long prompts. Retrieval (RAG) is often cheaper and more accurate.

**API, SDK.** An **API** is a way for programs to talk to a service over the internet. An **SDK** is a library that makes calling it easy, like the `anthropic` and `openai` Python packages.

**Messages and roles.** Chat APIs take a list of messages, each with a role: `user` (the person) and `assistant` (the model). The **system prompt** sets overall behaviour and rules.

**Streaming.** Receiving the answer token by token as it is generated, so the user sees text appear immediately instead of waiting for the full answer.

**Token cost.** APIs charge separately for input and output tokens, usually priced per million tokens; output tokens cost more. Cost per call ≈ input tokens × input price + output tokens × output price. Check the provider's price page; prices change often.

**Rate limit and retries.** Providers limit requests or tokens per minute. When you hit a limit (HTTP 429) or a temporary error, wait and retry with **exponential backoff** (wait 1 s, then 2 s, then 4 s…). The official SDKs already retry a few times.

**Ollama.** A tool to download and run open models on your own laptop with one command, for example `ollama run llama3.2`. Useful for free local testing and private data.

**Union-find (DSA).** A structure that tracks which items are in the same group, with near-constant-time `find` and `union`. Used to count connected components and detect cycles.

**Dijkstra's algorithm (DSA).** Finds the shortest path in a graph with non-negative edge weights, using a min-heap to always expand the closest unvisited node.

**Minimum spanning tree (DSA).** The cheapest set of edges that connects all nodes. Kruskal's algorithm sorts edges and adds them with union-find; Prim's grows the tree with a heap.

## End-of-week self-check

1. What is the difference between a base model and an instruction-tuned model?
2. Explain RLHF in three steps.
3. Logits are [1, 1, 1]. What are the probabilities at temperature 1? At temperature 0.1?
4. Which temperature would you use to extract fields from invoices as JSON, and why?
5. What is the KV cache and what does it cost?
6. Your prompt has 3,000 tokens and the answer 500 tokens. The (example) prices are $3 per million input tokens and $15 per million output tokens. What does one call cost? What do 10,000 calls a day cost?
7. Give three reasons LLMs hallucinate.
8. What two operations does union-find support, and what tricks make them fast?

**Answers**

1. A base model only continues text in the style of its training data. An instruction-tuned model has been further trained (SFT and preference tuning) to follow instructions and answer like an assistant.
2. (1) Collect human comparisons of pairs of model answers. (2) Train a reward model to predict which answer humans prefer. (3) Use reinforcement learning to update the LLM to produce answers with high reward, while staying close to the original model.
3. Equal logits give equal probabilities at any temperature: [1/3, 1/3, 1/3]. Temperature only changes the gaps between logits, and here there are none.
4. Temperature 0 (or very low), because you want the same, most likely, correct answer every time, not creative variety.
5. It stores the keys and values computed for earlier tokens so each new token only computes its own, which makes generation much faster. The cost is GPU memory, which grows with context length, batch size and model size.
6. Input: 3,000 × $3 / 1,000,000 = $0.009. Output: 500 × $15 / 1,000,000 = $0.0075. Total ≈ $0.0165 per call. For 10,000 calls: about $165 a day. (These are example prices; always check the real ones.)
7. The model predicts likely text rather than checking facts; the fact may be missing, rare or outdated in its training data; and prompts that demand an answer push it to guess instead of saying "I don't know". Decoding with randomness can also pick a wrong token.
8. `find` (which group is this item in?) and `union` (merge two groups). Path compression and union by rank or size make both nearly O(1) on average.
